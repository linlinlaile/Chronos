## Context

现有 `course_catalog.json` 按类别保存课程标题、播放时长、页码和位置，并按时长升序选择下一门课程。课程页面现在确认会直接提供可计学时，因此目录可以增加一个稳定的 credit metadata 层。实现仍需兼容旧目录、同步 Playwright 页面变化，并遵守现有真实播放和完成记录约束。

## Goals / Non-Goals

**Goals:**

- 将卡片和详情页的时长、可计学时解析为统一的课程记录。
- 在有限候选集上求解覆盖当前缺口的最短总播放时间组合。
- 详情页作为冲突时的权威来源，并将校正结果持久化。
- 在每门课程完成后重新读取/确认缺口，避免长期持有过期计划。
- 对旧目录和未知字段提供可观测、可恢复的降级行为。

**Non-Goals:**

- 不修改视频 `playbackRate`、`currentTime` 或平台网络请求。
- 不直接调用学习记录、心跳或学时写入接口。
- 不并发播放多门课程。
- 不保证未知学时课程参与最优组合。

## Decisions

1. **统一课程记录模型。** 在目录记录中保留 `duration_minutes`、`credit_hours`、`credit_source`、`category`、`key`、`page` 和 `position`。读取旧的 `duration` 字段时进行兼容映射；写回时逐步使用新字段，但保留旧字段以避免已有定位逻辑失效。

2. **字段解析分层。** 先从课程卡片提取候选字段用于建立目录；进入详情页后再次提取最终可计学时和时长。详情页有值时覆盖卡片值；两者冲突时保留详情页值并输出诊断。缺失字段使用显式状态 `credit_hours = None`，而不是 0。

3. **组合目标函数。** 对当前类别未完成且学时已知的候选课程，求满足 `sum(credit_hours) >= gap` 的组合。主排序为总播放分钟数，次排序为超出缺口的学时，再次排序为课程数量和单位时长效率。候选数量设置上限，避免课程目录过大时出现不可控搜索。

4. **采用有界动态规划/枚举混合算法。** 学时通常是 0.5 或 1.0 的小数，先将学时按最小精度缩放为整数，使用按缺口截断的动态规划保存最短总时长和回溯索引；当字段精度或候选数量异常时降级为按效率和时长排序的贪心选择，并记录降级原因。这样比单纯按比值贪心更能处理 0.5+1.0 与 1.5 的组合差异。

5. **计划是短生命周期的。** 只在选择类别或学时刷新后生成计划，每完成一门课就移除该课程并重新读取可用缺口。若面板暂时未到账，保留本地完成状态和计划失效标志，下一次刷新后再计算，不重复进入已完成课程。

6. **降级策略明确化。** 若整个类别没有任何可解析学时的课程，保留现有按时长队列作为兼容模式并打印警告；若只有部分课程有学时，则优先使用已知课程，未知课程仅在显式允许的兼容配置开启时作为最后候选。默认不把未知学时课程视为可覆盖缺口。

7. **测试以纯函数为主。** 将字段解析、目录归一化、组合求解和旧目录迁移设计为无浏览器依赖的辅助函数；Playwright 测试只覆盖卡片/详情页字段提取和校正触发，降低登录环境对算法验证的影响。

## Risks / Trade-offs

- [页面字段名称或格式变化] -> 集中维护字段选择器和数值解析规则；解析失败保留原始文本摘要并进入未知状态。
- [详情页学时与最终服务端到账不一致] -> 详情页只作为课程元数据权威来源，达标判断仍以学时面板实际已完成值为准。
- [候选课程过多导致组合搜索变慢] -> 限制候选数量和目标学时范围，记录搜索耗时，超限时降级为确定性贪心。
- [旧目录缺少新字段] -> 兼容读取旧 `duration`，标记待补全，避免静默赋予默认学时。
- [学时小数精度导致组合误差] -> 使用配置的最小学时单位缩放和统一 decimal/整数转换，禁止二进制浮点直接比较缺口。

## Migration Plan

1. 新增纯函数和单元测试，先验证字段解析、旧目录归一化和组合结果。
2. 扩展目录写入格式并支持从旧格式读取；首次进入详情页时补全记录。
3. 将主循环的“下一门课程”选择替换为基于当前缺口的短期计划选择。
4. 增加日志和统计，验证计划总时长、预计覆盖学时与实际到账学时的一致性。
5. 通过一次登录状态下的手动运行验证后再作为默认策略启用；失败时可回退到现有按时长升序队列，且不删除 `learned_courses.json`。

## Open Questions

- 课程卡片与详情页的可计学时字段是否在所有类别使用相同文本标签；若不一致，只影响选择器映射，不改变组合规格。
